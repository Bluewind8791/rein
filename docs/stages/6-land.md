# 6. land — 후처리

끝난 작업을 저장소마다 커밋 하나로 남깁니다. 커밋 메시지는 `6-land.md`에 씁니다. PR·push는 하지 않습니다.

- **워크트리 run** — 사용자가 한 번 승인하면 Rein이 워크트리에서 커밋하고, 그 커밋을 메인 작업 트리의 브랜치로 가져온 뒤 워크트리를 지웁니다.
- **워크트리 없이 열린 run**(워크트리 도입 전에 열림) — 스테이징까지만 하고, **커밋은 사용자가 직접 합니다.** Rein은 커밋하지 않고 묻지도 않습니다.

에이전트 지시: [skills/land/SKILL.md](../../skills/land/SKILL.md) · [skills/retro/SKILL.md](../../skills/retro/SKILL.md)

## 들어오는 길

- 통합 qa 통과 → 훅이 land로 옮김
- 사용자가 체크리스트를 직접 테스트하고 `/rein:land` 입력 → 훅이 모든 칸이 체크됐는지 확인

## 워크트리 run의 흐름

run은 처음부터 자기 워크트리(`<저장소>/.claude/worktrees/<slug>`, 브랜치 `rein/<slug>`)에서 작업했습니다. 그래서 메인 작업 트리 파일은 건드리지 않았고, 사용자가 같은 트리에서 병행하던 변경이 섞이지 않습니다. 워크트리를 언제 어떻게 만드는지는 [overview.md](../overview.md#워크트리)에 있습니다.

0. **메인 작업 트리로 돌아가기** — land는 메인 작업 트리에서 합니다. 세션이 워크트리 안에 있으면 먼저 `ExitWorktree`(keep)로 나옵니다. Windows에서는 세션이 잡고 있는 폴더를 지울 수 없어서, 나오기 전에는 `advance`가 거부합니다(`park`의 `폐기`도 같음).
1. **`6-land.md`** — 메인 세션이 커밋 메시지와 저장소마다 커밋할 파일 목록을 씁니다.
2. **`advance`(답 없이)** — 훅이 메시지가 있는지, 메인 작업 트리가 run을 시작한 브랜치에 있는지 확인하고 승인받을 내용을 돌려줍니다.
   - 저장소마다 넣을 브랜치와 커밋할 파일(계획 파일 중 바뀐 것)
   - 커밋하지 않고 워크트리와 함께 지워질 파일(계획 밖 변경, 예: 임시 파일). gitignore된 파일은 목록에 없고 함께 지워집니다.
3. 메인 세션이 사용자에게 묻고, 답(`커밋` 또는 `취소`)을 `advance`에 넘깁니다.
4. **`커밋`이면** 저장소마다 훅이 차례로 실행합니다. 저장소의 git hook(pre-commit 등)은 끈 채로 돌립니다. 검증은 qa가 이미 했습니다.
   1. 워크트리에서 그 파일만 이름으로 `git add -A --` 한 뒤 커밋
   2. 메인 작업 트리에서 `git cherry-pick`
   3. `git worktree remove --force`, `git branch -D rein/<slug>`
5. 다 들어가면 run이 닫히고 폴더가 `complete/`로 옮겨집니다. 다른 프로그램(편집기, 띄워 둔 서버 등)이 워크트리 폴더를 잡고 있으면, git은 파일을 지우고 등록을 풀지만 빈 폴더가 남습니다. 그 경우 무엇이 남았는지 사용자에게 알립니다.

### 멈추는 경우

멈추면 메인 작업 트리는 원래대로이고, 워크트리와 커밋은 남습니다. 사용자가 정리한 뒤 `advance`를 다시 부르면 다시 묻습니다. 이미 만든 커밋은 다시 만들지 않고, 이미 들어간 저장소는 건너뜁니다.

- 메인 작업 트리가 run을 시작한 브랜치가 아닌 다른 브랜치에 있음
- cherry-pick 실패 → `cherry-pick --abort`로 되돌림. 메인 작업 트리에 **스테이징된 변경이 하나라도 있거나**, 같은 파일의 커밋 안 된 변경이 있으면 git이 거부합니다. 다른 파일의 unstaged 변경은 괜찮습니다.
- run을 시작할 때 detached HEAD였던 경우: 메인 작업 트리가 지금 있는 브랜치에 넣습니다. 여전히 detached면 멈추고 브랜치로 전환하라고 안내합니다.
- 커밋 서명(`commit.gpgsign`)을 켠 저장소: 훅은 저장소 설정에 적힌 프로그램이 실행되지 않게 `gpg.program`을 막고 git을 돌리므로, 커밋이 실패하고 git의 오류를 보여 줍니다. 서명이 필요한 저장소라면 Rein 밖에서 커밋하고 `park`의 `완료`로 닫습니다.

## 워크트리 없이 열린 run의 흐름

1. **스테이징** — 메인 세션이 계획된 파일 중 `git status`에 바뀐 것으로 나온 것만 이름으로 `git add`.
2. **`6-land.md`** — 메인 세션이 커밋 메시지와 저장소마다 스테이징 목록을 씀. 사용자가 읽고 커밋할 때 쓰는 문서입니다.
3. **`advance`** — 훅이 확인합니다.
   - `6-land.md`가 있음
   - 스테이징 = 정확히 "계획된 파일 중 바뀐 것"
4. 통과하면 run이 닫히고 폴더가 `complete/`로 옮겨집니다. 메인 세션이 사용자에게 `6-land.md` 경로를 알리고, 넘길 파일(`handoff/`)이 있으면 적용 방법도 알립니다.
5. 사용자가 그 메시지로 직접 커밋합니다.

## 커밋 메시지

프로젝트 룰이나 저장소 문서에 커밋 규칙이 있으면 그것을 따릅니다. 없으면 기본 형식입니다.

```
[<참조>] <변경 요약>

<왜 바꿨는지>

<변경 전 동작. 변경 후 동작.>
```

`<참조>`는 `1-spec.md`의 `참조:` 값입니다. `없음`이면 대괄호째 뺍니다.

## 메인 세션이 커밋할 때

사용자가 시켜서 메인 세션이 `git commit`을 하면, 사용자 승인(`커밋`) 전에는 거부됩니다.
Rein 밖에서 이미 커밋했다면 `park`로 `완료 (Rein 밖에서 반영함)`를 골라 run을 닫습니다.

## 회고 (retro)

run이 닫히면(land 통과, 커밋할 것 없이 종료, `폐기`·`완료`로 park) `rein:retro`가 run 폴더와 세션 기록을 읽습니다.
Rein 플러그인이나 도메인 지식에 반영할 후보를 `retro.md`에 적고, 사용자가 남길 것을 고릅니다.
반영은 하지 않습니다 — Rein 저장소의 `learn` 스킬이 나중에 적용합니다.
